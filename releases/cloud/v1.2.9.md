# Cloud 1.2.9 正式发布

本版本将扫描会话的持久化解密密钥与管理台密码解耦，并增加可保留配置的出站代理开关。云扫描支持从拓展同步的线路配置中选用 javdb580.com 作为备用域。

## 主要变化

- 首次启动生成数据目录内的 `vault.key`（32 字节、0600）；登录管理台后，将已有的 v1 会话密文逐项迁移至 v2。之后容器重启不再需要重新登录即可解密 v2 会话。
- 管理台出站代理可直接关闭并保留已配置的地址与凭据；关闭时扫描及全局通道强制直连，重新开启时恢复原配置。没有开关字段的旧设置维持原行为。
- 云扫描候选域白名单增加 `javdb580.com`，保留 HTTPS、域名归一及仿冒域拦截。浏览器拓展的 cookie 采集白名单仍独立维护：启用 580 线路不保证旧会话在该域有效。
- 跨端 `untracked` 状态增加值无关性测试；不改变同步协议或整条 LWW 行为。

## 升级与备份

升级前备份宿主机完整 `data/` 目录及部署配置。升级后**登录管理台一次**，让已有的 v1 会话完成 v2 迁移；不要把管理台密码写入配置文件。确认会话有效、扫描正常后，检查 `data/vault.key` 为 32 字节且权限为 0600。

从本版本起，**数据库和 `vault.key` 必须一起备份和恢复**。丢失旧密钥后自动生成的新密钥不能解密旧 v2 密文，只能让拓展重新推送会话并再次登录管理台。回滚旧版二进制无法读取 v2 密文；需恢复升级前的完整数据备份或重新推送旧版会话。

Cloud 不会自动升级运行中的容器。Compose 升级示例：

```bash
docker compose -f compose.yaml pull
docker compose -f compose.yaml up -d
```

固定版本：`ghcr.io/javdbviewed/javdbviewed-cloud:1.2.9`。镜像 digest：

```text
sha256:4cef4e8319426664eaf25960bf794d3c1ed64b254b5d286f6bdeb1fca43ab495
```

升级后检查 `/health` 和 `/version`，确认 `version=1.2.9`、`buildNumber=git-4b477f028824`，并在管理台确认会话与扫描状态。
