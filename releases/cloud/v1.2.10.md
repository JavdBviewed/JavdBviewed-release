# Cloud 1.2.10 正式发布

本版本整理了管理台的导航与操作布局，统一后台任务入口，增加媒体库定时索引和多端索引融合，并修复会话持久化与版本检查的稳定性问题。

## 管理台与后台任务

- 后台任务独立放入侧边栏，统一查看新作品扫描、Emby/Jellyfin 与 115 媒体索引任务。任务列表补全来源、阶段、运行结果和异常信息，状态颜色更清晰。
- 媒体索引与新作品扫描设置入口移到页面上方；设置按用途归类，并提供设置目录与搜索，减少查找配置的层级。
- 调整列表、表头、按钮、圆角、间距和弹窗，窄屏使用便于阅读与操作的卡片布局；长配置弹窗保留可见的保存操作区。
- 任务历史可按类型清理，显示明确的范围、空状态、失败提示和完成反馈；保留未完成任务与续扫断点。
- 移除容易误解的新作品“存量清理”入口。

## 媒体索引与来源融合

- Emby/Jellyfin 支持可配置频率的后台索引任务。
- 115 索引使用请求间隔、日预算、限频退避与持久化断点，适合云端持续运行；需要显式授权后开启自动任务。
- 云端接收并融合各设备的来源报告。同番号可以保留多个文件，各设备、各来源独立管理；不要求拓展和云端互斥扫描。
- 支持桌面本地文件夹索引报告，聚合后供兼容的消费端判断是否入库；源删除后退役对应贡献，失败或不完整报告不当作空的完整扫描。
- 聚合索引只用于下发消费，不作为某台设备的本地扫描贡献回传。无番号的本地文件暂不纳入上云索引。

## 扫描线路与会话

- 管理台可编辑跨端共享的 JavDB 线路，按最后一次修改同步；任务和状态页面补全扫描线路与来源信息。
- 修正会话状态提示，使管理台登录与用于后台扫描的站点会话更容易区分。
- JavDB 会话上传成功后立即以持久化数据密钥保存，防止后续上传重新写回重启后不可解密的旧格式。未解锁、密文无效或密钥不可用时明确返回错误，并保留已有会话。

## 版本检查

- 默认先检查 GitHub 原站，失败后依次尝试 `gh.llkk.cc`、`gh-proxy.com`、`ghfast.top`，并显示实际检查来源。
- 每个地址最多等待 5 秒，全轮最多 25 秒；异常响应与无效清单自动顺延。显式配置的更新清单地址仍维持自定义地址优先。
- 页面请求被取消时，不再把 `context canceled` 保存为检查结果或覆盖已有正常缓存。

## 升级与备份

同步协议保持版本 2。媒体来源报告使用独立接口；请先升级支持来源报告的客户端，再启用共享来源的云端自动索引。混用旧版整份快照客户端时，无法保证严格的删除收敛。

升级前备份完整 `data/` 目录和部署配置，**数据库与 `vault.key` 必须一起保留**。已有 v1 会话仍需正常登录管理台或由兼容拓展重新上传以完成迁移；Cloud 升级本身不会恢复失效的站点会话。丢失旧密钥后，新生成的密钥不能解密旧 v2 密文。

Cloud 不会自动替换运行中的容器。固定版本镜像为：

```text
ghcr.io/javdbviewed/javdbviewed-cloud:1.2.10
```

使用发布中心 Compose 模板时，在 `.env` 中将 `CLOUD_IMAGE_NAME` 设为上述固定版本，再执行：

```bash
docker compose -f compose.yaml pull
docker compose -f compose.yaml up -d
```

升级后检查 `/health` 和 `/version`，确认版本为 `1.2.10`、构建号为 `git-a949e599352c`，并检查管理台中的会话、扫描和媒体索引状态。需要回滚时保留旧镜像；恢复数据应使用同一时点的数据库和密钥备份。
