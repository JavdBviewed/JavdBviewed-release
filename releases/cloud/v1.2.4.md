# Cloud 1.2.4 正式发布

Cloud 1.2.4 现已作为正式稳定版本发布。本版本主要解决多设备同步的合并正确性（条目级 LWW），并新增云侧新作品扫描、管理台数据视图与媒体源管理页面。

## 主要变化

### 同步合并（数据面）

- 媒体源（Emby/Jellyfin）同 id 的并发修改改为条目级 updatedAt 毫秒戳 LWW 合并，多设备同时改同一媒体源时按更新时间裁决，不再整表覆盖。
- 非 settings 实体（影片记录、新作、片单、演员等）合并同样改为条目级 LWW，退役 revision 裁决键；删除的墓碑语义保持不变。
- 同步协议新增 patch op：云端对非 settings 实体做白名单字段 overlay 合并，保留协议 v2 兼容窗口，拓展端无需改动即可继续同步。

### 云侧新作品扫描（新增）

- 云端按配置周期抓取订阅演员的作品页，新作品写入媒体库（限速、日上限、熔断、会话健康监控）。
- 管理台「新作品扫描」页：扫描状态 + 每轮扫描的后台任务记录（开始/耗时/状态/写入条数）。
- 支持手动「立即跑一轮」：跳过间隔门立即执行，总开关、熔断窗、日上限仍然生效。

### 管理台数据视图（新增）

- 媒体库五个视图：影片记录、新作、片单、演员、洞察，均支持搜索、筛选、分页与行级详情抽屉。
- 媒体源管理页：Emby/Jellyfin 源的查看与编辑；媒体库索引页给出各类型数据的服务端摘要。
- 总览页新增同步健康块：最近同步时间、7 天数据增量、部分拒绝面与设备活跃概览。
- 侧边栏精简为 5 个平铺入口，相关页面收进容器页做页内 tab 分类；媒体库 5 视图分页默认 10 条。

### 其他

- vault 条目支持 DELETE（硬删、幂等 204）。
- 部署文档补充明文 HTTP 使用警示与云库凭据风险边界。

## 数据兼容

- 服务端新增 `scan_runs` 扫描任务记录表，启动时自动建表，非破坏性。
- 合并裁决键从 revision 改为 updatedAt 毫秒戳：只影响多设备同时修改同一条目时的裁决结果，不做数据迁移，旧客户端与 1.2.4 服务端兼容。
- 无其他 DB schema 变更。

## 校验和

发布门禁产物见 CI 工件 `cloud-release-1.2.4`（`release/` 目录）：

```text
release/release-manifest.json  89e3999fa7db148d06b03dc0a00c4fae0177d6a9ca1abcc8eb7a706be4fb40c3
```

manifest 与镜像 OCI labels 的 commit/buildNumber/obfuscated 状态一致（commit=b02aa6e2946246259ba452bd9fc29b12c1695469，buildNumber=git-b02aa6e29462，obfuscated=true）。

## 已部署用户升级

Cloud 不会自动替换或重启你的容器。升级前请先在管理台的数据页面创建快照，并备份宿主机的 `data/` 目录。

如果你使用 Compose：

```bash
docker compose -f compose.yaml pull
docker compose -f compose.yaml up -d
```

需要固定在本版本或回滚时，将 `.env` 中的 `CLOUD_IMAGE_NAME` 改为：

```text
ghcr.io/javdbviewed/javdbviewed-cloud:1.2.4
```

本版本镜像 digest：

```text
ghcr.io/javdbviewed/javdbviewed-cloud:1.2.4@sha256:c5c9d228bebfcc8a5568b646b5285607198971a11dad3b7bdec6fecc0595bca7
```

部署后请访问 `/version`，确认 `version` 为 `1.2.4`、`buildNumber` 为 `git-b02aa6e29462`。

## 启动后检查

- 访问 `/health`，确认服务返回正常状态。
- 管理台可登录，五个数据视图与媒体源管理页正常打开。
- 任一客户端执行一次同步，确认正常无报错；多设备同时修改同一媒体源时按更新时间生效。
- （可选）在「新作品扫描」页点「立即跑一轮」，确认后台任务 tab 出现一条记录。
- 其余业务数据保持不变。
