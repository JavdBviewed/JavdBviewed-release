# Cloud 1.3.2 发布说明

发布对象 = `c59e5b7dc186042d21cf48c732d7ded1c298b065`（tag `cloud-v1.3.2`）。本版为基于 1.3.1（`2c3e411dea4bcb2f1d0e0709f04faf65f224e6e7`）的热修版，仅含两项修复，无其他变更。

## 一、下载任务状态刷新去除本地惩罚性退避

此前版本在下载任务连续失败后，会在云端本地拉长任务状态刷新的间隔（最长可拉至 2 小时）——即使 115 侧的临时限制已经恢复，任务状态仍会长时间不更新，表现为「提交得了、进度不动」。本版移除该本地退避锁：状态刷新保持固定间隔，115 侧限制解除后下载任务通道立即恢复。115 官方自身的限流行为不变，云端不再在其之上额外加锁。

## 二、下载相关错误透传 115 原始状态码

下载任务与 MCP 下载相关调用遇到上游拒绝时，此前多显示「115 服务暂时不可用」类笼统文案，真实原因被掩盖。本版起错误信息追加 115 原始状态码（形如「（原始状态 403/10029）」，至多三段），排障可直接区分限流、鉴权、参数类问题。REST 与 MCP 的错误分类与字段结构不变，仅文案更可读。

## 三、数据库

无数据库变更：相对 1.3.1 无迁移、无新增字段，可直接升级。升级前备份仍按惯例执行（data 目录与 vault.key 一并备份）。

## 升级

Cloud 不会自动替换运行中的容器。固定版本镜像：

```text
ghcr.io/javdbviewed/javdbviewed-cloud:1.3.2
```

使用发布中心 Compose 模板时，在 `.env` 中将 `CLOUD_IMAGE_NAME` 设为上述固定版本，再执行：

```bash
docker compose -f compose.yaml pull
docker compose -f compose.yaml up -d
```

镜像 digest 以本仓 `manifests/cloud/stable.json` 的 `latest.imageDigest` 为准（本次实取 sha256:0bef40557a11cbf19e908fb6f8307c61d66c3adad5d0cf26f61409777f2b61b0，与 registry 回执逐字一致）。

## 版本线说明

1.3.2 = 1.3.1 + 两项下载通道修复（`b414edd` 状态刷新去退避、`c59e5b7` 错误码透传）。从 1.3.1 直接升级即可；更早版本请先升 1.3.1（累计发布范围与变更详单见同目录 `v1.3.1.md`）。
