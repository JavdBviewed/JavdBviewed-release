# Cloud 1.2.6 正式发布

Cloud 1.2.6 现已作为正式稳定版本发布。本版本调整云侧新作品扫描的配置语义（管理台「接管」改为多端同步、最新写入为准，且可直接在云端开启扫描）、收紧扫描参数边界、出站代理支持账号密码认证核验，并新增快照保留天数自动清理策略。

## 主要变化

### 新作品扫描（配置语义与参数策略）

- 配置语义由「管理台接管」改为多端同步、最新写入为准：任何一端（拓展或管理台）最后写入的扫描配置生效，管理台是其中一个写入端；「接管」相关文案全站清除。
- 管理台可直接开关云扫描：设置页「扫描」块迁入「新作品扫描」状态页，新增云端写入端点 PUT /v1/admin/scan-config（总开关/间隔/批量三字段必填）；拓展端回读端点 GET /v1/scan/config 契约形状不变（source 取值集合 {admin, extension, default} 不变，语义改为最后写入方），旧版拓展兼容。
- 扫描参数策略收紧：间隔 60–1440 分钟（缺省 60），批量 1–50（每轮最多 50）；越界或历史遗留值由服务端钳制兜底，无需人工干预。
- 启动一次性迁移：若设置里存在 active 的管理台接管块，启动时并入共享 new_works_config 实体（cloud-admin 身份）并清除该块；无 active 块则 no-op，幂等带日志。

### 出站代理（增强）

- 代理配置拆为四个字段：协议 / 地址 / 账号 / 密码，支持带账号密码认证的代理。
- 「测试连通」增加代理认证核验（五态裁决：连通 / 认证失败 / 端口未开放 / 超时 / 其他），账号密码是否正确可以实际验出。
- 密码框新增显隐切换；修复无密码态下回读时占位密码 **** 被误预填、字面星号落库的问题。

### 数据管理（快照自动清理）

- 新增快照保留天数自动清理策略：缺省 60 天，0=关闭，上限 3650 天；每日检查一次，最新一份快照永远保留。
- 数据页快照提示文案对齐保留策略（移除「Cloud 不会自动清理任何快照」旧口径）。

### 界面

- 页内 tab 条由胶囊样式改为下划线指示样式。
- 后台任务卡头按钮归右对齐（刷新/清空不再居中）。

## 数据兼容

- 无 DB schema 变更、无新表。
- settings 新增 `snapshotRetention` 键（retentionDays：未设置=缺省 60、0=关闭）；`lastCleanupAt` 由服务端维护，均为普通 KV 合并，旧客户端/旧拓展不识别新键，不受影响。
- new_works_config 实体：启动时接管块一次性迁移（无 active 块=no-op）；历史越界扫描值由 worker 钳制兜底生效，无需人工改数据。
- 旧版拓展/客户端：GET /v1/scan/config 契约不变，回读兼容；PUT /v1/admin/scan-config 为管理台新端点，旧端不感知。

## 校验和

发布门禁产物见 CI 工件 `cloud-release-1.2.6`（`release/` 目录）：

```text
release/release-manifest.json  161577839544f49e7a5e3167c52b0ad7e3a26275760a0606587ba1ea73023a0f
```

manifest 与镜像 OCI labels 的 commit/buildNumber/obfuscated 状态一致（commit=4d337cfacfceadfab428a4d8f5f3aa025a366dda，buildNumber=git-4d337cfacfce，obfuscated=true）。

## 已部署用户升级

Cloud 不会自动替换或重启你的容器。升级前请先在管理台的数据页面创建快照，并备份宿主机的 `data/` 目录。

如果你使用 Compose：

```bash
docker compose -f compose.yaml pull
docker compose -f compose.yaml up -d
```

需要固定在本版本或回滚时，将 `.env` 中的 `CLOUD_IMAGE_NAME` 改为：

```text
ghcr.io/javdbviewed/javdbviewed-cloud:1.2.6
```

本版本镜像 digest：

```text
ghcr.io/javdbviewed/javdbviewed-cloud:1.2.6@sha256:bd80675b48426e04db3ac59ab02d78b65a0244675556f2a533e708687a1b480b
```

部署后请访问 `/version`，确认 `version` 为 `1.2.6`、`buildNumber` 为 `git-4d337cfacfce`。

## 启动后检查

- 访问 `/health`，确认服务返回正常状态。
- 管理台可登录；「新作品扫描」状态页可见扫描设置卡（多端同步口径）与后台任务记录；设置页不再有「扫描」子 tab。
- （可选）配置出站代理后点「测试连通」，确认代理与账号密码可用；在「新作品扫描」页点「立即跑一轮」，确认后台任务记录正常写入。
- （可选）数据页设置快照保留天数，确认每日自动清理策略按预期生效（最新一份永留）。
- 任一客户端执行一次同步，确认正常无报错。
- 其余业务数据保持不变。
