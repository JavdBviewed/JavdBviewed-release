# Cloud 1.2.11 正式发布

本版本修复 115 网盘 token 在跨端 settings 同步中被陈旧整包翻回旧值的问题（JavdBviewed 拓展 #58）：某台设备刷新 token 后，另一台持有旧配置快照的设备在下一个同步周期整包推送，云端按整包 last-write-wins 存储旧 token，再拉取回本地即表现为 token 周期性"翻回旧值"（约 2 分钟一次）。

## 115 网盘 token 同步修复

- settings 合并对 drive115 token 三件套（`v2AccessToken` / `v2RefreshToken` / `v2TokenExpiresAt`）引入组级时间戳 LWW：以 `v2RefreshTokenIssuedAtSec` 为组戳，较新的 token 组在冲突中整体胜出，陈旧整包不再覆盖。
- token 组作为原子单元替换：组内缺失的键会被删除，避免新旧 token 跨端混血导致刷新失败。
- incoming 组全空时不传播清除：本地有效的 token 组不会被"空值"清空（既有已知限制保持不变）。
- 组外会话键（`v2AuthMode` / 刷新状态等）维持既有键级保护；配置键（clientId / downloadDir / enabled 等）口径不变，仍随 settings 整包裁决。
- 语义与拓展 2.1.6 客户端拉取侧合并、emby mediaServers 条目级 LWW 逐字对齐；服务端与客户端各自独立防护，单边先行也能阻止本地翻回。

## 回归测试

- 新增双设备真实 store push 冲突回归用例：陈旧设备以更高 revision 推送旧 token 组后，存储与拉取两侧均保持新 token，修复前该用例精确复现 #58 症状。

## 升级与备份

同步协议保持版本 2，无数据格式变更。升级前备份完整 `data/` 目录与部署配置，**数据库与 `vault.key` 必须一起保留**。

Cloud 不会自动替换运行中的容器。固定版本镜像为：

```text
ghcr.io/javdbviewed/javdbviewed-cloud:1.2.11
```

使用发布中心 Compose 模板时，在 `.env` 中将 `CLOUD_IMAGE_NAME` 设为上述固定版本，再执行：

```bash
docker compose -f compose.yaml pull
docker compose -f compose.yaml up -d
```

```text

```
