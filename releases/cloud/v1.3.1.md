## 二、drive115 MCP 工具五病灶修复（1.3.0 → 1.3.1）

115 开放接口部分响应的实际形态与旧实现的解析假设不符，导致三类外部可见故障；本版逐一修正：

- **`drive115_search` 此前恒失败**：115 搜索成功响应为顶层 `{state, count, data:[…]}`（`count` 与 `data` 平级），旧实现把 `data` 数组误按 map 反序列化，报「data not json」类错误，任何关键词都搜不出结果。现返回 `{count: 命中总数（115 原样透传，数字/字符串均容）, files: 命中条目数组（保留 115 字段名）}`。
- **`drive115_move_files` / `drive115_copy_files` 计数恒 0**：115 批量写成功时 `data` 实测为空数组，旧实现按 `len(data)` 上报条数永远得 0，调用方误以为「操作了 0 条」。现上报**提交条数**（去重后提交 id 数）；`data` 非空时原样透传供取证。
- **`drive115_delete_files` 同型计数问题**：现返回提交（去重后）ids 列表，语义同上。
- **`drive115_file_info` 拒因误导**：对文件（非文件夹）或不存在目标，115 `get_info` 返回 `state:false`，旧实现统一映射为「服务暂时不可用」，掩盖真实原因并诱发无意义重试。现拒因改为「目标不存在或不是文件夹（文件详情请用 `drive115_list_files` 在父目录中查找）」；真正的服务不可用路径不受影响。
- **trash_revert 等其余 115 面**：ID 列表解析与提交条数口径同步修正（同一套 helper 重构：`drive115IDList` / `postDrive115Raw`）。

## 三、信封宽容解析与响应形态指纹（加固）

- 115 通用信封（`state`/`code`/`data`）解析从严格类型判定重写为宽容判定：`state` 布尔/数字/字符串的假值（`false`/`0`/`"false"`/`"0"`）才算业务异常，缺省或 null 不再误杀成功响应；`code` 数字或字符串数字折算，不可解析时交 `state` 兜底。
- 响应结构解析失败不再裸报「无法识别的数据」：错误 Detail 内附**形态指纹**（sha256 前 12 位十六进制 + 响应长度 + 头尾各 6 字符，转义后无凭据），仅供服务端日志与留档排障，不出现在对外 API 响应中。
- 业务码判定顺序固定：driveCodeError 先判（不被结构错吞）→ state 假值 → data 反序列化，并配 14 形态 `state×code` 矩阵测试防误报误杀。

## 四、MCP 健壮性审计修复

- **`-32700` 回填请求 id**（超时黑洞的协议层根因）：请求体超限与坏 JSON 的错误响应此前无 `id`，客户端 SDK 无法关联 pending request 只能挂到超时；现从前缀嗅探回填（顶层裸 `id` 键、1KB 窗口、显式 null 不回填），`MaxBytesReader` 超限单独回 `FILE_TOO_LARGE` 并写明 262144B 请求体上限口径。
- **`drive115_upload_file` 能力边界如实化**：`contentBase64` 加 `maxLength 258048`（=raw 189KB，为请求体墙留信封余量）——此前「240KB 恒超时」实为撞墙且无 schema 拦截；description 按实现逐条改写：`sourceUrl` 为云容器主动拉流全量缓冲（非 115 代拉、非流式），仅公网直链、不支持 Cookie/Authorization 透传与 Range 断点续传，GB 级不可行。
- **`media_index_search` 口径补充**：明确检索对象为本地落库索引（非实时打 115）、扫描深度/间隔/每日预算约束与 Emby 快照性质，及与 `drive115_search` 的互补关系。
- **工具改名考证**：`download_task_*` 无改名的全历史实算与改名登记纪律成文。
- move/copy/delete 返回语义的 payload 断言补齐（测试面）。

## 五、drive115 视频播放族三工具（MCP 工具 35 → 38）

新增 `drive115_video_play` / `drive115_video_history` / `drive115_video_subtitle`（均只读 scope）：play 透传 115 播放地址并回显 `user_agent` 与 `ua_hint`（播放地址与 UA 绑定，需以回显 UA 请求）；history/subtitle 字节级透传；`pick_code` 校验与下载面共用；UA 参数限 256 字符无控制字符（防头注入）。管理台「MCP 接入」页条目与计数已同步。

## 六、同步计划 UI 修正

- `/sources` 配置同步弹窗加宽一档（560→680），同步计划摘要对齐调度真语义：每日时间点模式下成功即落下一时间点、间隔不参与（如实注明「至多一轮，同步间隔不生效」）；纯周期档位文案按每 N 天/小时/分钟递进，不再误写「每日」。
- 每日时间点模式下置灰同步间隔输入与频率 chip，附不生效提示。

## 对外部 MCP 客户端的影响

- **键名零破坏**：`moved`/`copied`/`deleted`/`count`/`files` 等返回键名不变，只修语义与失败面；此前「能调通但数值错误」的客户端逻辑（如按 `moved=0` 判断失败）在升级后将拿到真实提交条数。
- **行为变化**：`drive115_search` 从恒失败变为正常返回；`drive115_file_info` 对文件/不存在目标的报错文案变化（拒因更准确，勿再按「服务暂时不可用」文案做重试判断）；批量写面在 115 返回非空 `data` 时会附加透传 `data` 键（`""`/`null`/`[]`/`{}` 时不附）；`-32700` 错误响应现可携带请求 `id`；base64 上传超 189KB 由撞墙超时变为即时 schema/体积错误。
- 工具总数 35 → **38**（drive115 族 13 → 16）。
- 管理台「MCP 接入」页 drive115 工具目录描述与 `tools/list` 下发文案逐字一致。
