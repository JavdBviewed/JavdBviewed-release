# Cloud 1.3.0 正式发布

本版本是 1.x 运维线的最大一次发布：MCP 生态成型（35 个工具）、115 网盘 token 全生命周期治理（生命周期审计、扫码续期、后台自动刷新、RT 判死告警与 SMTP 通知）、管理台信息架构与设计系统统一、下载任务页与 OpenList 提供方、索引失败退避与调度时段窗等。自部署升级前请按「升级与备份」完整备份，并通读新增环境变量清单与安全注意。

本次发布同 commit 包含 2.0 多站点同步（site-data）域的代码，默认休眠、无启用入口、不参与任何行为，不构成功能发布。

## MCP 工具生态（35 个工具）

- MCP 服务工具面从 31 个扩展到 35 个：补齐 115 网盘上传链（`drive115_upload_file` 支持 base64 内容与 URL 拉取二选一、sha1 秒传零直传、超分片阈值自动 OSS 分片并发）、下载任务、索引与日志侧的运维工具。
- 每个工具带最小 scope 门禁（MinScope），调用统一落审计：actor 记 MCP token id 或 admin 用户，token 一律只记 12 位十六进制指纹，明文绝不入审计与调用日志。
- MCP token 管理页每行新增「调用记录」快捷跳转，直达日志中心 `token=` 精确过滤视图。

## 115 网盘 token 生命周期治理

- 新增 `drive115_token` 生命周期审计：上传（`token115.upload`）、签发/落库（`token115.issue`）、刷新（`token115.refresh`，含后台自动刷新来源 `scheduled-refresher`）全程可追溯。
- 后台自动刷新器（方案 A：Cloud 独占主动刷新）：AT 剩余低于提前量到点即刷，事件驱动精确唤醒取代 30 分钟粗 tick；落新组（管理台上传/扫码授权）即时重排唤醒；一切失败只记日志并在下一次唤醒自然重试，过期后重排节奏收敛为 min(5 分钟, Interval) 防失败热循环。
- RT 判死语义：拓展侧标记 RT `invalid/expired` 后云端一律停刷，绝不盲刷；判死触发 `rt_dead` 邮件告警（同组去重），引导用户扫码续期。
- 新增扫码续期：管理台可发起 115 扫码授权换新令牌组（内置默认 client id，可用 `JDB_115_SCAN_CLIENT_ID` 覆盖）。
- SMTP 邮件通知：RT 判死、token 失效等事件可发邮件；管理台「通知设置」可配置，`JDB_SMTP_*` 环境变量按项压过库内配置（`JDB_SMTP_ENABLED=false` 强制关闭）。

## MCP token 管理增强

- 明文回看：由「只显示一次、关闭不可找回」改为管理端可反复回看与复制；旧版 hash-only 存量行明文不可恢复，界面明确标注并引导吊销重建；vault.key 变更导致解密失败时如实提示，不伪造明文。
- 名称与备注编辑：token 行可改显示名与备注；变更统一落 `mcp.token_updated` 一条审计，metadata 只记前缀指纹与变更字段名列表。
- token 级 IP 白名单：每个 token 可配 CIDR/精确 IP 列表，非空即强制——命中放行、未命中拒绝（`mcp.ip_denied` 审计记 token 指纹与来源 IP，均非明文）；留空为不限制。

## 日志中心

- 新增统一日志中心页：运行日志、审计事件、MCP 调用记录一处汇聚，支持来源/级别/关键字与 `token=` 精确过滤。
- MCP 调用与拒绝事件接入日志中心（与审计同源），管理员排障不再登服务器翻容器日志。

## 下载任务与 OpenList 提供方

- 新增下载任务页：任务分标签查看、目标路径可选、进度与失败原因直读。
- 新增 OpenList/云盘下载提供方：OpenList 配置卡收敛为令牌直连单模；管理台保存配置反向写回属主 settings 快照（双向同步），改配置不再需要各端手工重下发。
- OpenList 封存静态 token 支持管理台明文回看（`openlist.token_revealed` 审计，成功/失败均记录，审计 metadata 不落明文）。

## 索引退避与调度时段窗

- 媒体索引失败退避：连续失败按指数退避封顶（`MEDIA_INDEX_BACKOFF_MAX_MIN`，默认 240 分钟），服务器长时间宕机不再反复硬撞。
- 索引任务支持时段调度窗，可在低峰时段集中处理。

## 新片扫描 AR 过滤修正

- 「不追踪 AR」判定旧口径大小写敏感且要求词边界，漏杀 `AR1234`/`ar-0923`/`99AR 021`/全角 `ＡＲ１２３４` 等站方形态；收敛为两支匹配：独立大写 AR 词（保留旧语义）+ AR/ar/全角紧邻 ≥2 位数字（允许 ≤3 位数字前缀段），并以生产真实标题与 NWC payload 做防误杀夹具（`ZMAR`/`START`/粘连长数字等不杀）。
- 新片扫描 worker 此前从未注入日志回调，排除计数与过滤解析失败在生产静默丢弃；本次已接线扫描观测日志，过滤命中情况可在日志中心取证。

## 管理台：信息架构与设计系统

- 设计系统底座落地：输入框/表单控件样式全线统一，弹窗与同步对话框交互收敛，三页帮助图标口径统一。
- AT/RT 状态分列显示；设备与接入申请列表分页档位改为 5/10/20/50（默认 20）；通知设置独立标签页；MCP 反馈提示条等文案清理（移除私有仓库原因句等历史话术）。

## 升级与备份

数据库迁移均为增量，但本版本迁移项较多：升级前**必须**完整备份 `data/` 目录与 `vault.key`（token 明文回看、115 令牌与 OpenList 封存值全部依赖 vault.key 解密，丢失不可恢复）。回滚到 1.2.x 不保证可行，需要回滚时请用备份恢复。

Cloud 不会自动替换运行中的容器。固定版本镜像为：

```text
ghcr.io/javdbviewed/javdbviewed-cloud:1.3.0
```

使用发布中心 Compose 模板时，在 `.env` 中将 `CLOUD_IMAGE_NAME` 设为上述固定版本，再执行：

```bash
docker compose -f compose.yaml pull
docker compose -f compose.yaml up -d
```

镜像地址：`ghcr.io/javdbviewed/javdbviewed-cloud:1.3.0`（与生产在跑的 1.3.0-wave11 构建同源，同 commit `4c7a0db`）。镜像 digest 以本仓 `manifests/cloud/stable.json` 的 `imageDigest` 字段为准，更新检查端亦以该文件为权威源。

## 新增环境变量清单

全部有默认值，按需设置；未设置即沿用默认行为。

| 变量 | 用途与默认 |
| --- | --- |
| `JDB_TRUST_FORWARDED_FOR` | 反代部署下来源 IP 审计口径开关。默认关（只信连接层 RemoteAddr）；经 HTTPS 反代访问时设为 `1`，否则 IP 记录与 token IP 白名单都以反代内网 IP 为准，白名单形同失效。见下文安全注意。 |
| `JDB_115_AUTO_REFRESH` | 115 AT 后台自动刷新开关，默认开；`0/false/off` 关闭。 |
| `JDB_115_REFRESH_AHEAD_SEC` | 自动刷新提前量（到期前多少秒唤醒刷新），默认 900。 |
| `JDB_115_REFRESH_INTERVAL_MIN` | 自动刷新兜底巡检周期（分钟），默认 30。 |
| `JDB_SMTP_HOST` / `JDB_SMTP_PORT` / `JDB_SMTP_TLS` / `JDB_SMTP_USER` / `JDB_SMTP_PASS` / `JDB_SMTP_FROM` / `JDB_SMTP_TO` | SMTP 通知参数，按项覆盖管理台「通知设置」的库内配置；`JDB_SMTP_TO` 逗号分隔多收件人。 |
| `JDB_SMTP_ENABLED` | 通知总开关（env 侧）；`false` 强制关闭，压过库内开启。 |
| `JDB_NOTIFY_DEDUPE_H` / `JDB_NOTIFY_RECOVERED` / `JDB_NOTIFY_LINK` | 同事件去重窗口（小时）/是否发恢复通知/邮件内管理台链接。 |
| `MEDIA_INDEX_BACKOFF_MAX_MIN` | 媒体索引失败退避封顶分钟数，默认 240。 |
| `JDB_115_UPLOAD_MAX_MB` | MCP 上传内容大小上限（超限本地拒绝、零外发），默认 100。 |
| `JDB_115_UPLOAD_PART_SIZE_MB` | 分片阈值（MB），超过自动走 OSS 分片并发，默认 8。 |
| `JDB_115_UPLOAD_CONCURRENCY` | 分片并发度，1-8，默认 4。 |
| `JDB_115_SCAN_CLIENT_ID` | 扫码续期使用的 115 开放平台 client id；默认内置值，自有应用可覆盖。 |

## 安全注意

- **token 明文回看的审计口径**：MCP token 明文仅在管理端（requireAdmin）接口返回；OpenList 封存 token 回看走独立 `reveal-token` 端点并记 `openlist.token_revealed` 审计（成功与失败均记录，审计 metadata 不落明文）。所有 MCP 调用、拒绝与生命周期审计一律只记 token 指纹，不记明文。共享管理台账号或给管理员开 VPN 前，请评估"可反复回看"带来的明文暴露面。
- **IP 白名单与信任头开关的关系**：来源 IP 统一按 `JDB_TRUST_FORWARDED_FOR` 口径解析——默认只信连接层 RemoteAddr（直连部署的防伪口径）；开启后取 `X-Forwarded-For` 首项，且首项必须是合法 IP 字面量才采信，否则回落 RemoteAddr。开启的前提是"首个 XFF 项由你的受信反代写入"；若存在客户端可直达容器端口的路径，必须保持关闭，否则白名单可被伪造头绕过。
- **vault.key 纳入备份**：本版本大量能力（明文回看、自动刷新、OpenList 封存值）依赖 vault.key；请与 `data/` 一同异地留存。
- 本版本同 commit 携带 2.0 site-data 域休眠代码：默认不启用、无对外行为，升级数据格式不受影响，不视为功能发布。
